# Geräteabgleich

Der Chief Server hält Watchlist, Journal, Positionen, Risikoeinstellungen, Makroereignisse, Alarmzustände und Alarmhistorie in einem versionierten lokalen Workspace. Beim ersten Klick auf **Abgleichen** wird der lokale Stand auf einem leeren Server gespeichert; auf einem bereits belegten Server erscheint zuerst ein Konflikt. Nach einem erfolgreichen Abgleich prüft Chief alle 30 Sekunden auf Änderungen, solange die Seite sichtbar ist. Bei zwei konkurrierenden Änderungen erscheint ein Konflikt; Chief überschreibt keinen Stand automatisch. Vor einer lokalen Übernahme wird der verdrängte Stand unter `chief-sync-local-backup-v1` im Browser gesichert und ein JSON Download gestartet. Der Server bewahrt bei jedem Überschreiben die vorige Version als `workspace.json.bak` auf. Falls eine Sicherung fehlschlägt, wird die Übernahme abgebrochen.

Der Server bindet standardmäßig nur an `127.0.0.1`. Auf demselben PC können damit mehrere Browser denselben Workspace nutzen. Die portable Einzeldatei bleibt ohne Abgleich offline; mit Serveradresse und Zugriffscode kann sie denselben versionierten Workspace laden und speichern. Für diesen Dateiursprung muss der Chief Server mit `CHIEF_SYNC_TOKEN` gestartet werden.

Der Abgleich synchronisiert die fachlichen Daten. Live Provider Cache, Kurs Snapshots und der pro Gerät gewählte Live Modus bleiben lokal. Ein Workspace Backup im Command Center sichert diese zusätzlich als JSON.

Für ein Smartphone im lokalen Netz müssen `CHIEF_HOST`, `CHIEF_SYNC_TOKEN`, `CHIEF_TLS_KEY_PATH` und `CHIEF_TLS_CERT_PATH` vor dem Start gesetzt werden. Chief startet bei Netzwerkfreigabe ohne Zugriffscode und vertrauenswürdiges TLS Zertifikat nicht. Das Zertifikat muss für die Adresse gültig sein, die das Smartphone öffnet. Der Zugriffscode bleibt nur für die Browsersitzung gespeichert. Es wurde kein Cloud Dienst eingerichtet.

In der portablen Datei unter **Geräteabgleich** die Chief Serveradresse und denselben Zugriffscode eintragen, dann **Abgleichen** wählen. Die Adresse muss mit `https://` beginnen; `http://localhost` oder `http://127.0.0.1` ist nur auf demselben PC erlaubt. Der Server erlaubt Anfragen aus der Datei nur mit gesetztem Server Zugriffscode und prüft diesen bei jedem Abruf und Schreibvorgang. Die Adresse bleibt lokal gespeichert, der Zugriffscode nur für die Sitzung.

Der Serverstand liegt standardmäßig unter `.chief-data/workspace.json` und wird nicht in Git eingecheckt. Vor einem Gerätewechsel zuerst auf dem bisherigen Gerät **Abgleichen**, dann auf dem zweiten Gerät **Serverstand übernehmen**. Ein initialer Konflikt auf dem zweiten Gerät ist beabsichtigt, weil dessen lokale Startdaten vom bestehenden Workspace abweichen.
